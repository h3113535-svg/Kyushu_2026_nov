# Kyushu_2026_nov v1.11.20 Changes

## Scope
- Owner-only shared-data deletion in the app.
- No itinerary/content changes.
- No Hero or palette changes.

## What changed
1. Added configurable trip-owner identity via `KYUSHU_OWNER_EMAIL` or `KYUSHU_OWNER_UID`.
2. Shared delete buttons are rendered only for the configured owner.
3. Delete handlers also verify owner identity before removing shared data.
4. Covered explicit shared delete actions for foods, shopping, expenses, imported map places, and custom booking items.
5. Local-only PDF/offline/cache removal stays device-local and is not owner-restricted.
6. Added `FIREBASE_OWNER_DELETE_SETUP_v1.11.20.md` explaining the required Realtime Database Rules hardening for true server-side enforcement.
7. Bumped version/cache from `1.11.19` / `11119` to `1.11.20` / `11120`.

## Firebase Seed
- No content change.
- No Firebase Seed re-import needed.

## Important
- Until `KYUSHU_OWNER_EMAIL` or `KYUSHU_OWNER_UID` is configured, shared delete is disabled for everyone.
- Firebase Rules must also enforce owner-only delete if you want this to be a real permission boundary rather than only an app UI guard.
